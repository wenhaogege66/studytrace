## 新增数据库 CI

`.github/workflows/ci.yml` 增加独立的 `database` job，随 Pull Request、`main` 和 `feat/v03-*` 分支推送执行。

- 沿用仓库已有的 Checkout／Node.js Actions，不新增第三方 Action。
- 使用 Node.js 22 和固定的 `npx --yes supabase@2.75.0`，不读取线上 Secret、不链接托管项目。
- 将配置和迁移复制到 GitHub 运行器的临时目录；项目 ID 包含当前运行编号和重试编号，容器与数据卷不复用其他运行。
- 保留 Postgres、GoTrue、PostgREST 和 Kong；排除无关的 Studio、Storage、Realtime、邮件测试、Edge Runtime 与日志等容器。参数已按本机同版本 CLI 的 `start --help` 核对。
- 自动枚举所有 `supabase/tests/*.sql`，逐个通过运行器上的 `psql --no-psqlrc --set ON_ERROR_STOP=1` 连接隔离数据库的本地发布端口 `54322` 执行，任一 SQL 错误使任务失败。这样兼容洞察套件的本地管理角色重连，避免把容器内的 `5432` 与主机发布端口混淆。当前共 9 个套件，未来新增文件也会被纳入。
- 在 `always()` 清理步骤中，仅对本次运行生成且通过格式校验的项目 ID 执行 `stop --project-id ... --no-backup`，不使用 `--all`。
