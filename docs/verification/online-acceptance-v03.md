## 托管数据库 Advisors 与权限核验

### 性能

发布主流程在 `2026-11-08T10:10:26Z` 读回：38 条 `unused_index` INFO，没有缺失外键索引提示，没有高风险项。新库尚无真实使用负载，未使用索引提示不构成删除必要约束或索引的理由。

### 安全

最新安全检查无 ERROR，但不是零警告：共 42 条 WARN、13 条 INFO。

- 27 条 WARN 为 `authenticated` 可执行的 SECURITY DEFINER RPC 提示。此类接口采用身份／所有权校验与受限原子操作；核心隔离已被 SQL 测试覆盖，但不能仅凭测试通过宣称所有特权代码零风险。
- 15 条新增 WARN 为开启匿名登录后的 `auth_allow_anonymous_sign_ins`：13 个 public 业务表和两个 cron 扩展表。匿名身份获得的是 `authenticated` 角色，不是未登录的 `anon` 角色，需结合权限与策略判断。
- 13 条 INFO 为私有表开启 RLS 但未设置策略的提示，属于普通客户端默认拒绝的设计，不是为所有用户放行。

本轮在 `2026-11-08T10:13:39Z` 左右直接只读核验了新库 catalog：

| 对象                               | 已核实权限与策略                                                                                                                                                               | 结论                                                                                |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| 13 个 public 业务表                | 全部开启 RLS；`anon` 无表访问权限；策略仅面向 `authenticated`，以 `auth.uid() = user_id` 约束读取，写入策略同时核验所有权，相关表另核验父记录归属                              | 匿名用户访问本人的业务记录是产品预期，不等于公开访问所有记录                        |
| 原始事实表                         | `observation_runs`、`session_segments`、`task_lifecycle_events`、`task_step_events` 对 `authenticated` 无直接读写授权                                                          | 聚合、受限导出与生命周期 RPC 是独立的受控入口                                       |
| `cron.job`／`cron.job_run_details` | 两表开启 RLS，扩展策略为 `username = CURRENT_USER`、面向 PUBLIC；表级存在 PUBLIC SELECT，运行详情还存在 PUBLIC DELETE                                                          | 这是按数据库角色隔离，不是按应用 `user_id` 隔离，不能单看策略便声称已满足业务所有权 |
| cron 可达性                        | cron schema 对 `anon` 与 `authenticated` 均无 USAGE；两角色不继承 postgres、supabase_admin 或 service_role；未发现普通用户可执行、调用 cron 的 public SECURITY DEFINER wrapper | 当前普通客户端不能使用这些 cron 对象；扩展默认表／函数授权不等于实际可达            |

部分 cron schedule／unschedule 函数虽然有 PUBLIC EXECUTE，但当前 schema USAGE 仍是阻断边界。因此本次未发现这 15 条匿名访问提示对应的已证实越权，不为消除提示而关闭产品匿名功能，也未修改扩展默认 DDL。以后若增加 cron schema USAGE、公开 wrapper 或调整 Data API 暴露范围，必须重新审计。告警仍需保留在交付记录中。
