# 过程观察 v0.3：实现与验收边界

## 实现范围

- 浏览器 Worker 以目标 4 FPS 运行 MediaPipe Face Landmarker；EfficientDet-Lite0 最多每秒辅助检测一次人物和可见手机。COCO 模型不识别平板，也不把“手机可见”直接当作违规。
- 模型与 WASM 自托管。EfficientDet-Lite0 float32/v1 SHA-256：`40338edf5ec70d43e318b0a716a84d4564cd1802759a7a07170c7e43796dbf58`。来源与许可证指向见 `public/mediapipe/NOTICE.md`。
- 有效连续帧才累计覆盖；单帧失败、低光/过曝、无效姿态矩阵、多个人物、超过一秒采样间隔均中断连续判断。没有面部但画质有效可记录“未在画面”，并不虚构姿态基线。
- 校准需要稳定姿态和足够连续样本。Worker 错误、消息错误、两秒单帧超时会有限重启，最多两次；失败后进入不可用状态，计时与手动复盘继续可用。视频冻结三秒或轨道中断会关闭摄像头。
- 技术帧健康与本地姿态有效性分开：画质可用但纸笔低头遮住面部时，本地姿态/离开判断为未知，仍可在明确授权下交由云端检查可见设备使用。没有人物辅助模型且无人脸时也不虚构离开。云端稀疏窗口不冒充全程观察覆盖。
- 关闭、暂停、页面隐藏、身份切换与导航离开停止采样。传入 Worker 的 Bitmap 在成功、未知和失败路径均释放；过期帧号不会清除新帧的 watchdog 或产生新事件。

## 云端处理

默认未启用；需要用户主动勾选，且本次观察约定至少限制手机或平板。每二十秒一组四张 JPEG，覆盖最近约六秒；最多一个在途请求。图像最长边为 480 像素，单帧请求上限 180,000 字符，总 JSON 上限 750,000 字节。

`/api/observation/analyze` 使用用户 JWT 验证身份及数据库会话快照，原子预留额度。服务端调用百炼后，只有服务端 Secret 可提交结构化结果；客户端不能伪造 `cloud_vision` 事件。完成时再次检查授权、原 Auth Session、本次学习状态与摄像头版本，迟到结果废弃。

默认模型 `qwen3.7-flash`，非思考模式，无自动模型切换，SDK 自动重试关闭。数据库限制每用户每分钟三次、每日 360 次及全站每日 2,000 次。未知窗口、模型不清楚和间隔过大的窗口不能连成持续行为；同一规则两组有效窗口出现线索才形成候选，提醒冷却十分钟。事件时间只代表当前采样窗口，不代表两组之间持续看见。

只在私有窗口记录中保存数字型输入/输出 Token 用量，便于上线后核验真实成本；随窗口记录七天清理，不记录请求图像或提供商原文。

独立防滥用额度收据仅保存请求编号、单向散列主体和时间，不依赖可删除的学习记录。删除计划或清空数据不会返还额度；按六天目标、每小时清理，正常调度下不超过七天。它不包含学习内容或媒体。

部署变量（全部只由平台配置，不进入 Git）:

- `QWEN_API_KEY`：必须使用已轮换的新 Key。
- `QWEN_BASE_URL`：沿用可信百炼 OpenAI 兼容地址。
- `QWEN_VISION_MODEL`：可选，默认 `qwen3.7-flash`。
- `QWEN_VISION_ENABLED=true`：仅在人工确认模型免费额度和“免费额度用完即停”后配置。缺失时安全关闭云端。
- `SUPABASE_SECRET_KEY`：仅服务端，用于提交经过提供商处理的结构化结果，绝不进入浏览器包。

本应用不将帧、视频、音频、关键点或任意模型原文写入数据库、对象存储、日志或错误追踪。调用失败只返回通用错误，不打印 SDK 错误对象。百炼官方[隐私说明](https://help.aliyun.com/zh/model-studio/privacy-notice)明确说明其会依法存储模型和应用调用产生的数据；授权界面披露该边界，不承诺第三方零留存。

## 授权与覆盖接口

授权版本 `2026-11-08.v1`。`get_my_consents()` 返回以 `cloud_observation`、`ai_reports`、`weekly_reports` 为键的对象；每项含 `granted/version/granted_at/revoked_at/updated_at`。未出现或版本不一致均视为未授权。`set_my_consent(p_feature,p_granted,p_version)` 是唯一客户端写入口；AI 报告撤回会同步撤回每周自动报告，匿名身份不能启用自动报告。

`VisionPanel.onValidCoverage({deltaMs,totalMs,at})` 只报告成功有效连续推理的增量。整合后以约五秒批次调用：

```
record_observation_coverage(
  p_session_id uuid,
  p_expected_state_version bigint,
  p_camera_version bigint,
  p_sequence bigint,
  p_valid_milliseconds integer
) -> bigint
```

`sequence` 为当前摄像头版本下递增的批次编号；重试复用原序号和增量。单批最多 10,000 ms，数据库再以实际服务端间隔封顶，重复序号不重复累计。关闭状态 RPC 前先提交剩余有效增量。历史旧观察区间默认有效覆盖为零，不能把旧摄像头开启时长追认为有效识别。事实报告聚合应使用 `observation_runs.effective_milliseconds`，而非未扣除失败区间的摄像头时长。

## 人工验收表（发布前）

1. 先轮换已暴露 Key，确认免费额度、模型可用性和用完即停；再打开云端开关。
2. 屏幕与纸笔分别测试稳定校准、正常低头、转头、离开、低光、遮挡、多人、摄像头拔出、冻结和断网。确认失败时不虚增有效覆盖。
3. 手机和平板分别测试“允许/不使用/不观察”，手持操作与仅桌面放置分开。观察框确实覆盖目标；每个目标行为五次，至少四次正确记录。未知计为漏检，不排除未知样本美化准确率。
4. 正常学习二十分钟，错误提醒不超过两次；持续可见的约定外行为目标六十秒内出现线索。记录实际值，不能只写通过。
5. DevTools Network 过滤 `/api/observation/analyze`：未授权零请求；启用后只出现低频四帧序列，不出现麦克风、关键点或持续视频。关闭、暂停、后台、撤回和身份切换之后没有新图像上传；故意延迟响应不能产生提醒。
6. 逐条确认、解释正常学习操作、忽略及删除事件；只有用户确认线索才可参与长期事实规律。
7. 桌面与手机、键盘/触控查看授权文字、有效覆盖、云端连接与失败原因，摄像头拒绝时任务和手动复盘完整可用。
